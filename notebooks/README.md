# Kaggle wrappers

The notebooks in this directory are intentionally thin. Upload this repository and the restricted corpus through private Kaggle resources, update `REPO_DIR`, and execute the command-line implementation. Do not copy training logic into notebook cells or publish a Kaggle dataset containing the corpus. The local `artifacts/e2_kaggle_source.zip` is private, generated, ignored, and must be rebuilt after source changes; never stage it.

The E2-only wrapper restores the saved manifest versions and latest complete Trainer checkpoint from the three-epoch run, resumes to a total of five epochs, and executes every command with checked exit status. It then performs validation, freezing, test evaluation, and an artifact-only export that excludes the corpus.

## Final E1-E3 workflow

The repository-root `e2qwen3-qlora.ipynb` is the consolidated private Kaggle workflow. Despite its historical filename, it runs E1, resumes the full E2 Trainer state from three to exactly five epochs, and runs the separately labeled custom E3 retrieval experiment. The unavailable official `knowledge_v2` E3 remains blocked.

The notebook is organized as a CRISP-DM report rather than only a training launcher. It includes business and success criteria; dataset provenance and a fresh audit; seeded real examples; split, length, vocabulary, quality, leakage, and knowledge-coverage analysis; demonstrations of the exact Fairseq, Qwen, and retrieval representations; explicit Fairseq preprocessing; model configuration and learning-curve displays; validation/test metric plots; paired-bootstrap confidence intervals; output-length and qualitative comparisons; automatic rule-based and manual error-analysis status; limitations; and deployment guidance. Set `SHOW_PRIVATE_EXAMPLES=False` before sharing even a screenshot outside the authorized group. `EDA_SAMPLE_SEED`, `QUALITATIVE_SAMPLE_SIZE`, and `FIGURE_DPI` control the reproducible report outputs.

Attach the restricted `zh-vi` corpus and the complete output of the three-epoch E2 Kaggle run, including `work/e2_qwen3_8b_qlora_vi_zh_v1/trainer/checkpoint-546`. Select a GPU, enable Internet for the configured Git revision and pinned Qwen download, keep notebook sharing disabled, and use **Save & Run All**.

The recommended input route is a private Kaggle Dataset added through **Input → Add Input**. As a fallback, the notebook contains an optional Google Drive acquisition cell. The prepared all-model bundle contains `zh-vi/`; scoped `checkpoint/` and `work/` artifacts for E1, E2, and custom E3; all validation/test predictions and metrics; `Error_Analysis.py`; and optionally `manual_sample.jsonl`. Set `GOOGLE_DRIVE_BUNDLE_URL` and `GOOGLE_DRIVE_BUNDLE_SHA256` after uploading it. The verified bundle is extracted under `/kaggle/temp` and discovered automatically. If the cloned source commit lacks `Error_Analysis.py`, the notebook recovers the identical bundled copy. Do not put input data in `/kaggle/working`, and do not use an anyone-with-link Drive share unless the restricted-data policy permits it.

The consolidated notebook keeps its clone, corpus, micromamba-managed Fairseq environment, and Hugging Face cache under `/kaggle/temp`. Current Kaggle images need not provide `conda`, so the notebook downloads a checksum-pinned standalone micromamba binary and creates the Python 3.10 environment from `environments/fairseq.yml`. It writes only allowlisted private archives to `/kaggle/working`: one archive per experiment and `group10_e1_e3_kaggle_results.zip` containing the selected model artifacts, manifests, validation/test predictions and metrics, paired comparisons, the shared 100-sentence annotation sheet, the input/output workbooks produced by the root-level `Error_Analysis.py`, generated `analysis/figures` and `analysis/tables`, and checksums. The automatic workbook labels are heuristic diagnostics and must not be described as human judgments. If an adjudicated `manual_sample.jsonl` is attached, the notebook preserves and summarizes it instead of regenerating it. These outputs contain restricted or derived course data and must not be published.

Setup cells are safe to rerun in the same Kaggle VM: the notebook verifies and reuses an existing repository clone, corpus copy, Fairseq environment, and completed E1/E3 stages. When both attached Fairseq stages pass structural, configuration, checkpoint-hash, and row-count checks, the notebook skips Fairseq environment creation, preprocessing, and training entirely. It never deletes an existing run merely because a cell was executed twice.

Because the notebook clones `REPO_URL` at `REPO_REF`, both `Error_Analysis.py` and the notebook changes must be committed and pushed before a Kaggle run. The preflight fails with an explicit message if the cloned commit does not contain the script.
